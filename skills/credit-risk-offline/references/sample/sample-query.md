## 样本通用查询（非流程）

> 下列动作都是纯查询，不推进状态机，也不要求样本处于特定阶段；因此不单列为流程，而是作为任意阶段可调用的通用能力。

适用范围：`S1 ~ S5` 全阶段。

包含但不限于：
- 查询样本列表：`status`
- 查询单个样本状态：`status --key <key>`
- 查询样本详情：`get --key <key>`
- 查询样本统计信息：`info --key <key>`
- 查询样本报告路径：`report --key <key>`

使用规则：
- 当用户明确说“样本看一下 / 样本查一下 / 看下样本 / 查下样本 / 列一下样本 / 展示样本”时，默认走查询动作，不要误路由到流程
- 查询动作可以作为流程内辅助步骤存在，但本身不构成流程节点，也不改变样本状态
- 若用户一边查询一边表达推进意图（如“看下状态，能确认的话就继续”），先查再根据结果接入对应流程

回复规则：
1. 单样本回复前，先读取 `status --key <key>`
2. 在消息最后补充状态 例如：
   ```
   📌 当前状态：S4 — 已登记报告，可以确认样本了 ｜ 下一步：执行 confirm 确认样本
   ```
3. 若 `sample_status[key]` 不存在，直接提示状态未初始化
4. 多样本总览时，默认只汇总状态，不主动下钻到每个样本的 `get / info / report`
5. 用户后续点名某个样本，再按单样本规则继续
