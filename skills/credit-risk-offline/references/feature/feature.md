## 特征层定位

- 本文件负责特征层流程编排,并补充特征执行所需的最小字段约束
- 当前进入本文件前,`project_root` 应已由 `references/common/project-bootstrap.md` 确认完成
- 统一脚本别名 各个命令默认用 $FEATURE_SCRIPT 来执行 除非写出完整命令
  - 别名定义在 SKILL.md「命令别名」，直接使用 `$FEATURE_SCRIPT`

## 特征状态机与推进边界

| 状态 | 含义 | 推进方式 | 是否停留等待人工 |
|------|------|----------|------------------|
| F0 | 初始化,空状态| 流程一:添加特征 推进到 F1 | 否 |
| F1 | 特征组已添加,待筛选 | 流程二:执行特征筛选 推进到 F2 | 否 |
| F2 | 已完成特征筛选,待生成筛选报告 | 流程三:生成筛选报告 推进到 F3 | 否 |
| F3 | 已生成筛选报告,待人工查看并继续特征探查 | 用户查看筛选报告后 继续流程四:生成单特征探查报告 推进到 F4 | 是 |
| F4 | 已完成特征探查,待确认 | 流程五:确认特征组 推进到 F4 | 是 |
| F5 | 特征组已确认 | 可继续进入模型层 | 视后续流程而定 |

- 特征查询能力(如查看特征列表、状态、详情、筛选信息、报告)不推进状态机,可在 `F1 ~ F5` 任意阶段调用,详细见 `references/feature/feature-query.md`

## 流程一:添加特征

> 触发条件:用户明确要求新增特征 / 添加特征 / 开始特征工程 / 创建特征组,或当前会话处于未完成的 `add` 流程并继续补充 `sample_key`、`eval_label`、来源参数或导出文件路径。
> 这里的"当前会话"只指本轮对话内已建立的上下文,不包含 memory、系统注入的历史摘要或旧会话检索结果。

### 边界说明

- 流程一覆盖本地文件和数据表两类来源,不拆成并列流程;来源不同只影响取数准备与来源专属参数
- 只处理 `F0 → F1`
- 必须拿到已确认的 `sample_key` 才能继续;未确认样本必须切换到 sample 流程,不得跳过
- `eval_label` 必须显式确定,不能依赖默认回退
- `precheck` 不通过时停止 add,不得跳过检查直接执行
- 来源一旦锁定为 table,add 参数必须继续用 table 口径(`source_type=table`、`source_ref=原始库名.表名`、`feature_file_path=导出文件路径`),不得因输入变成本地路径而退化成本地文件来源

### 执行步骤

1. 确认项目与入口
   - 用户只说"新增特征 / 添加特征 / 创建特征组"时,默认先回到项目确认 / 项目选择
   - 若用户在本轮消息里明确指定项目,或明确说"继续当前项目新增特征",且当前存在合法 `project_root` 绑定证据,则可直接进入特征入口
   - 若当前会话已存在明确且刚确认的 `sample_key`,必须优先继承,不重复要求用户再次提供;这里仅指本轮会话内刚完成确认的样本,不包含历史会话或 memory 中残留的 sample_key
2. 确认 `sample_key`（按优先级依次判定）
   - **继承**：同会话刚完成样本 confirm 且用户明确继续进入特征层 → 直接继承，不重复问
   - **用户指定**：用户给了 key → 校验是否已确认；未确认则停止 feature add，切换到 sample 流程
   - **都不明确** → 获取样本与特征组的归属关系，按特征新增入口模板展示并让用户选择：
     1. 执行 `$SAMPLE_SCRIPT status` 获取样本列表
     2. 执行 `$FEATURE_SCRIPT status` 获取特征组列表（含 sample_key）
     3. 按 feature 的 sample_key 归属到对应样本下方
     4. 按特征新增入口模板渲染：有特征组的样本下方缩进展示，无特征组的样本不展示子行
     - 优先展示 `confirmed=true` 的推荐样本，只保留高价值字段：`sample_key` / `labels` / `sample_desc`(有值时) / `update_datetime`
     - 已确认样本多时按 `update_datetime` 倒序只展示最近 3 个
     - 未确认样本不全量展开，只展示最近更新的少量候选作为补充提示
   - **唯一例外**：当前项目下只有一个已确认样本且用户接受默认使用 → 可自动使用，否则 Agent 不得自行替用户决定
   - 特征新增入口模板见 `feature-template-reply.md`「特征新增入口模板」
3. 确认样本唯一标签 `eval_label`
   - 执行 `$SAMPLE_SCRIPT info --key <sample_key>` 获取样本标签信息
   - 若只有 1 个 label,默认使用该 label
   - 若有多个 label,展示候选并引导用户明确选择
4. 确认来源类型(本地文件 or 数据表)
5. **本地文件**:直接使用原文件;`source_ref` = 原路径,`feature_file_path` = 原路径,`feature_name` 从原始文件名推断
6. **数据表**:
   - 执行 `$DB_SCRIPT table_export_sql --table <库名.表名>`
   - 脚本完整输出直接转给用户,不做归纳,只提示用户手动执行
   - 用户执行 SQL 后,把导出的文件路径发回
   - 拿到导出文件后,`source_ref` = 原始库名.表名,`feature_file_path` = 导出文件路径,`feature_name` 基于原始表名推断(不得因输入变成导出文件而改按导出文件名重算)
7. 执行 `precheck --sample-key <sample_key> --feature-file-path <路径> --eval-label <label>`
   - Agent 按推断规则补齐字段;推断过程内化,不对用户输出推断中间结果
   - **feature_name 清洗**:去扩展名/取表名最后一段 → 小写 → 非字母数字转下划线 → 连续下划线折叠 → 去首尾下划线;超 50 字符精简保留核心词
   - **feature_desc**:可基于文件名或表名提炼中文描述,优先表达业务含义,不做逐词机翻;无法稳定判断则留空,不强行生成
   - precheck 不通过:停止 add,列出不一致项,提示用户修正后重新预检查
8. precheck 通过,展示特征添加确认卡(见 `feature-template-reply.md`「特征添加确认卡模板」);展示前必须做来源一致性校验
9. 用户确认后执行 `add ...`
10. 执行 `status --key <key>` 刷新状态进入 F1,自动衔接「流程二:执行特征筛选」,不额外等待用户确认

## 流程二:执行特征筛选

> 触发条件:特征组状态进入 `F1`,或用户明确要求「跑特征筛选 / 执行筛选 / 继续筛选 / 刷新筛选结果」。

### 边界说明

- 流程二是自动推进流程,不是人工确认流程
- 当前流程只处理 `F1 -> F2`
- 若 `select` 执行失败,直接转述脚本输出,不脑补原因

### 执行步骤

1. 先确认 `project_root` 与 `feature_key`
2. 使用 `exec background=true` 启动筛选命令：`select --key <key>`（后台运行，无超时限制）
3. 使用 `process poll timeout=120000` 等待输出（阻塞最多 2 分钟，有阶段进度输出时立即返回）
4. 每次 poll 返回后向用户同步当前阶段进度；若进程仍在运行，继续下一轮 poll
5. 进程完成后，执行 `status --key <key>` 刷新状态 进入F2
6. 若状态进入 `F2`，默认自动转入「流程三:生成筛选报告」，不额外等待用户确认

## 流程三:生成筛选报告

> 触发条件:特征组状态进入 `F2`,或用户明确要求「生成筛选报告 / 刷新筛选报告 / 补登记筛选报告」。

- 报告模板:`references/feature/feature-template-select-report.md`

### 边界说明

- 流程三是自动推进流程,不是人工确认流程
- 流程三只处理 `F2 -> F3`
- `F3` 是人工查看筛选报告的停留节点

### 执行步骤

1. 先确认 `project_root` 与 `feature_key`
   > ⚠️ 执行前必须读取 `references/feature/feature-template-select-report.md`
2. 按 `references/feature/feature-template-select-report.md`「报告生成步骤」执行（获取数据→渲染→登记路径→写入→刷新状态），提炼核心结论+关键发现（保留在上下文中备用）
3. 基于步骤2提炼的核心结论+关键发现，严格按 `feature-template-reply.md`「筛选报告回复模板」逐项对齐反馈；不得自行简化或改写措辞

## 流程四:生成单特征探查报告

> 触发条件:特征组已处于 `F3`,且用户明确表示已查看筛选报告,或明确要求「生成单特征探查报告 / 生成 detail report / 刷新单特征报告」。

### 边界说明

- 流程四是重点特征探查执行流程,不是最终确认流程
- 当前流程只处理 `F3 -> F4`
- 只要成功登记至少 1 份单特征探查报告,状态即可推进到 `F4`
- **所有特征均可探查**，不限于入选特征；淘汰特征的探查报告同样有价值，可帮助理解淘汰原因
- 报告生成完成后,应先向用户反馈探查结果;用户可选择进入确认环节,或继续探查其他特征
- **淘汰特征探查的补充说明**：若 `decision.status` 为 `Dropped`，报告的「一、核心结论」和「五、综合判断」中必须明确淘汰阶段、淘汰原因，并判断淘汰是否合理（明显失效 / 擦线出局 / 有一定价值但不值得保留）

### 执行步骤

1. 先确认 `project_root`、`feature_key` 与目标 `feature`
   > ⚠️ 执行前必须读取 `references/feature/feature-template-detail-report.md`
2. 先执行 `report --key <key> --feature <feature>`，检查是否已有探查报告
   - 如果已有 → 提示用户"该特征已有探查报告，是否需要重新探查？"，附上报告路径，等用户确认
   - 如果没有或用户确认重新探查 → 继续步骤 3
3. 按 `references/feature/feature-template-detail-report.md`「报告生成步骤」执行（获取数据→渲染→登记路径→写入→刷新状态），提炼核心结论+关键发现（保留在上下文中备用）
4. 基于步骤3提炼的核心结论+关键发现，严格按 `feature-template-reply.md`「单特征探查回复模板」逐项对齐反馈；不得自行简化或改写措辞
5. 用户若要求继续探查其他特征，则继续留在流程四处理下一个目标特征

## 流程五:确认特征

> 触发条件:用户明确表达要确认当前特征组,或在单特征探查报告生成完成后进入确认引导。

### 边界说明

- 流程五只处理 `F4 -> F5`
- 若当前状态不是 `F4`,不得执行 `confirm`
- `confirm` 前必须先调用 `get_confirm_summary` 展示确认摘要，由用户主动确认；不再提示"请先查看报告"

### 执行步骤

1. 先确认 `project_root` 与 `feature_key`
2. 执行 `status --key <key>`,检查当前状态
3. 按状态分流:
   - `F1`:当前还不能确认,需先继续特征筛选
     → 话术:「特征组还未筛选，请先执行 `select`」
   - `F2`:当前还不能确认,需先继续生成并登记筛选报告
     → 话术:「筛选已完成但筛选报告未生成，请先执行 `set_select_report`」
   - `F3`:当前还不能确认,需先查看筛选报告;确认继续后,再生成并登记单特征探查报告
     → 话术:「筛选报告已生成，请先完成至少一个特征的单特征探查后再确认」
   - `F4`:进入确认前摘要环节
   - `F5`:特征组已确认,直接提示可进入下一层
4. 若当前状态为 `F4`:
   - 执行 `get_confirm_summary --key <key>` 获取确认摘要
   - 按「确认前摘要回复模板」向用户反馈（标题="筛选结果概要"）
   - 循环等待用户回复意图:
     - ✅ 确认 → 跳出循环，继续步骤 5 执行 confirm
     - ➕➖ 调整特征 → 用户给出特征名及动作，执行 `fix_select_features --key <key> --actions '<JSON>'`，按「确认前摘要回复模板」反馈（标题="调整完成"，含操作结果），继续循环
       - `--actions` 为 JSON 字符串，key 为特征名，value 为 `add`（从全量补充到入选）或 `delete`（从入选中逻辑删除）
       - 示例：`--actions '{"f_risk_score_1":"add","f_overdue_hist_cnt":"delete"}'`
     - 🔍 继续探查 → 跳出循环，引导回到流程四
5. 用户明确确认后,执行 `confirm --key <key>`
6. `confirm` 成功后引导保持不变:
   - 若当前在 model 上下文:继续原流程
   - 否则提示:「✅ 特征组 `{key}` 已确认(F5)。下一步可以开始模型训练,要继续为这个特征组进入模型层吗?」
