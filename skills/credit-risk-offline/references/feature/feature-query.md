## 特征通用查询（非流程）

> 下列动作都是纯查询，不推进状态机，也不要求特征组处于特定阶段；因此不单列为流程，而是作为任意阶段可调用的通用能力。

适用范围：`F1 ~ F5` 全阶段。

包含但不限于：
- 查询特征组列表：`status`
- 查询单个特征组状态：`status --key <key>`
- 查询特征组详情：`get --key <key>`
- 查询筛选结果摘要：`info --key <key>`（返回 `select_summary`、`select_stages`、`select_excel_path` 等）
- 查询Excel筛选报告路径：`info --key <key>` 取 `select_excel_path`
- 查询筛选报告路径：`report --key <key>` 返回 `select_report` 路径
- 查询单特征探查报告路径：`report --key <key> --feature <feature>` 返回 `detail_report[feature]` 路径
- 查询筛选报告内容：根据 `report --key <key>` 返回的路径读取 md 文件内容
- 查询单特征探查报告内容：根据 `report --key <key> --feature <feature>` 返回的路径读取 md 文件内容

使用规则：
- 当用户明确说“特征看一下 / 特征查一下 / 看下特征 / 查下特征 / 列一下特征 / 展示特征”时，默认走查询动作，不要误路由到流程
- 查询动作可以作为流程内辅助步骤存在，但本身不构成流程节点，也不改变特征状态
- 若用户一边查询一边表达推进意图（如“看下状态，能确认的话就继续”），先查再根据结果接入对应流程
- 用户在查看筛选报告后，若继续说“看前几个特征 / 看第几个特征 / 看某一段特征 / 看指定哪些特征”，默认按查询动作处理，使用 `get_select_features` 返回对应筛选结果明细，不直接进入单特征探查流程

回复规则：
1. 单特征组回复前，先读取 `status --key <key>`
2. 先给状态提示，再继续正文，例如：
   ```text
   📌 当前状态：F4 — 已完成特征探查，可以确认特征组了 ｜ 下一步：执行 confirm 确认特征组
   ```
3. 若 `feature_status[key]` 不存在，直接提示状态未初始化
4. 多特征组总览时，默认只汇总状态，不主动下钻到每个特征组的 `get / info`
5. 用户后续点名某个特征组，再按单特征组规则继续
