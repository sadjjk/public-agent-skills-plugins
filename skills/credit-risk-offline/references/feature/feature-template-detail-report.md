# 单特征探查报告模板

## 执行约束

> ⚠️ **Agent 必读**:生成报告时,先执行 `feature get_detail_report_data --key <feature_key> --feature <feature_name>` 获取完整数据,再将下方「Markdown 模板」中的所有 `{{PLACEHOLDER}}` 替换为真实内容后写入文件。
> 每个占位符都必须替换,禁止遗漏任何一个。写入前自检:文件中不得出现任何 `{{` 或 `}}` 字符串。
> 本文件只负责 feature detail 报告展示规则;字段语义、数据来源与阶段含义统一以 `feature get_detail_report_data` 返回结果为准。

---

## 报告生成标准步骤

1. 执行 `feature get_detail_report_data --key <feature_key> --feature <feature_name>` 获取报告所需完整数据。
2. 完成 Markdown 渲染。
3. 若某章节数据缺失,按下文缺失/降级规则明确说明,不得留空,也不得编造结论。
4. 执行 `set_detail_report --key <key> --feature <feature_name>` 登记并获取脚本返回的标准报告路径。
5. 将渲染内容写入该路径。
6. 执行 `feature status --key <key>`,确认单特征探查报告写入后特征组状态已推进到 `F4`。

---

## 数据来源说明

单特征探查报告生成时,统一基于以下命令获取数据:

```bash
$FEATURE_SCRIPT get_detail_report_data --key <feature_key> --feature <feature_name>
```

说明:
- `get_detail_report_data --key <feature_key> --feature <feature_name>`:用于获取「一、核心结论」「二、特征概览」「三、分块诊断」「四、分箱风险趋势图」「五、综合判断」「六、关键发现」所需数据

报告输出路径由 `set_detail_report` 脚本返回,不再硬编码默认路径

## 占位符填充规则

### `{{FEATURE_DESC_OR_NAME}}`
优先取 `feature_desc`;若为空则回退到 `feature`。

### `{{FEATURE_KEY}}`
取顶层 `key`;若缺失则回退到 `basic.feature_key`。

### `{{FEATURE_NAME}}`
取顶层 `feature`。

### `{{DATETIME}}`
优先取 `generated_at`;若缺失,则使用当前时间,格式 `YYYY-MM-DD HH:MM`。

### `{{FEATURE_OVERVIEW_TABLE}}`
优先来自 `basic`、`decision`、`profile_detail`、`summary_detail`、`corr_detail`,渲染为 Markdown 表格。

推荐表头固定:

| 模块 | 关键结论 |
|---|---|

推荐覆盖以下内容:
- 特征定义:来自 `feature`、`feature_desc`
- 最终决策:来自 `decision.stage_no` + `decision.stage_name_zh` + `decision.status`
- 淘汰原因 / 保留结论:来自 `decision.reason`
- 数据质量:来自 `profile_detail`
- 区分能力:来自 `summary_detail.iv`、`summary_detail.ks`、`summary_detail.auc`
- 稳定性:来自 `summary_detail.psi_max`
- 风险方向:来自 `summary_detail.rc_min`、`summary_detail.mono`
- 相关性:来自 `corr_detail.max_abs_corr`

要求:
- 不要求所有行都必须出现;缺失则降级省略
- 表格内容以结论句为主,不要把所有原始字段原封不动堆进去
- 比例值优先转百分比展示,避免 `1.0` / `0.005555` 这类阅读歧义
- 特征名展示优先使用"英文名(中文释义)"形式;若无 `feature_desc`,则只展示英文名

### `{{CORE_CONCLUSION}}`
固定输出 3~4 条短结论,使用 emoji 编号(1️⃣ 2️⃣ 3️⃣ 4️⃣)。

必须覆盖:
- 当前特征最终在何阶段被淘汰或保留
- 主导问题是什么
- 数据质量是否存在明显异常
- 区分能力、稳定性、风险方向、相关性中最值得优先关注的一个核心结论

写法要求:
- 先给结论,再给数字支撑
- 这里负责总览性结论,优先概括全局,不展开重复证据链
- 结论前置,不写铺垫
- 可少量使用 `⚠️`、`🚨`
- 若 `decision.status` 为 `Dropped`,必须明确指出淘汰阶段和原因
- 若 `psi_max`、`rc_min`、`mono`、`max_abs_corr` 等字段存在明显异常,应直接点名,不要写成模糊表述

### `{{DETAIL_DIAGNOSIS}}`
固定按以下顺序组织,缺块可降级省略,但顺序不要乱:

1. `### 1. 数据质量与分布画像`
2. `### 2. 区分能力与稳定性`
3. `### 3. 分箱表现`
4. `### 4. 相关性观察`

#### 1)数据质量与分布画像
优先基于 `profile_detail` 输出。

推荐关注:
- `dtype`(数据类型)
- `missing_rate`(缺失率)
- `zeros_rate`(0 值占比)
- `unique_num`(唯一值个数)
- `unique_rate`(唯一值占比)
- `top1_rate`(最高频取值占比)
- `top1_value`(最高频取值)

推荐写法:
- 先用 1 段概览当前画像特征,再补 1 组紧凑指标列表或小表格
- 指标展示优先使用"英文变量名(中文释义)"形式
- 若比例值小于等于 1,优先转成百分比呈现
- 段末给一句结论,回答"问题是不是出在数据质量本身"

#### 2)区分能力与稳定性
优先基于 `summary_detail` 输出。

推荐关注:
- `iv`(信息量)
- `ks`(区分度)
- `auc`
- `psi_max`(最大稳定性偏移)
- `rc_min`(最小风险一致性)
- `mono`(单调性)

推荐写法:
- 先写整体判断,再引用关键数字
- 若 `decision.reason` 已直接说明淘汰原因,应与本段分析呼应
- 若存在明显异常值,如 `psi_max` 超阈值、`rc_min < 0`、`mono < 0`,必须直接点明
- 各阶段指标分布若有展开,必须显式写具体指标名,如 `IV 分布`、`PSI 分布`、`RC 分布`,禁止写成泛化的"指标分布"
- 段末给一句结论,回答"它是完全无效,还是可用但不稳"

#### 3）分箱表现
优先基于 `bin_detail` 输出，分两块展示：

**A：全量分箱 (bin_group = Total)**

全量展示所有 Total 分箱，确保 count 总和与样本量一致。

「分箱」列直接使用 `bin_label` 字段（已含序号前缀如 `00_`、`01_`），禁止再拼接 `bin_index` 导致序号重复。

推荐表头固定：

| 分箱 | count(样本数) | count_rate(样本占比) | bad(坏样本数) | bad_rate(坏样本率) | iv_bin(单箱信息量) | lift(提升度) |
|---|---:|---:|---:|---:|---:|---:|

**B：按月异常分箱 (bin_detail.anomaly_bins)**

当 `anomaly_bins` 非空时展示。按月拆分的分箱中，挑选最值得关注的样例 (2–5 个)，优先选：
- psi_bin 最高的分箱 (跨期漂移最大)
- bad_rate 与 Total 同分箱偏差最大的分箱
- iv_bin 与 Total 同分箱偏差最大的分箱

展示时需注明所属月份 (bin_group)，并与 Total 同分箱数据对比，说明偏差方向。

「分箱」列直接使用 `bin_label` 字段，禁止再拼接 `bin_index`。

若 `anomaly_bins` 为空，整块省略，不写"无异常分箱"占位。

推荐表头固定：

| 月份 | 分箱 | count(样本数) | count_rate(样本占比) | bad(坏样本数) | bad_rate(坏样本率) | iv_bin(单箱信息量) | psi_bin(单箱稳定性偏移) | lift(提升度) |
|---|---|---:|---:|---:|---:|---:|---:|---:|

⚠️ **字段完整性约束**：anomaly_bins 表格中所有列必须从返回数据中取值（`count`/`count_rate`/`bad`/`bad_rate`/`iv_bin`/`psi_bin`/`lift`），禁止用 `-`/`N/A` 占位。若某字段确实不存在于返回数据中，需明确标注"字段缺失"而非省略。

**两块共同要求：**
- 优先解释"哪个箱贡献了主要信息量""哪个箱带来了主要漂移"
- 段末给一句结论，回答"问题出在没有区分力，还是出在跨期分布变化"

#### 4)相关性观察
优先基于 `corr_detail` 输出。

推荐关注:
- `max_abs_corr`(最大相关系数)
- `top_related_features`

标题固定为：`**相关系数最高的样例**`
推荐表头固定:
| 相关特征 | corr(相关系数) | abs_corr(相关系数绝对值) |
|---|---:|---:|

要求:
- 以下为 Top N 相关特征举例（由 `_CORR_TOP_LIMIT` 控制，默认 3），非全量
- 明确说明当前特征是否存在较强同源冗余
- 如果 `corr_detail` 为空,不要臆测,直接写"当前无相关性明细"
- 段末给一句结论,回答"它是不是独立信号,还是更像特征簇中的一个成员"

### `{{PLOT_REL_PATH}}`
取 `payload_full["plot"]["rel_path"]`,即分箱趋势图相对于报告目录的相对路径(如 `imgs/Top1_fake_feature_029.png`)。
若 `payload_full["plot"]` 为空(图片生成失败),则省略整个「四、分箱风险趋势图」章节。

### `{{FINAL_JUDGEMENT}}`
固定输出 1 段总结性判断。

必须回答:
- 这个特征是"质量差""区分弱""不稳定""相关性高"中的哪一类问题为主
- 当前淘汰是否合理
- 它更像"明显失效""擦线出局"还是"有一定价值但不值得保留"

写法要求:
- 用自然中文,不要机械复述上文
- 可以一句话先总括,再拆 2~3 个支撑点
- 若数据不足,不要做过强判断

### `{{KEY_FINDINGS}}`
基于「一、核心结论 / 二、特征概览 / 三、分块诊断 / 四、分箱风险趋势图 / 五、综合判断」客观归纳,固定输出 4~6 条结论型发现;若确实无明显异常,可直接写 1 条"🟢 暂无明显异常"。禁止编造问题,也不能只是把前文数字机械重复一遍。

格式要求:
- 每条以前缀 emoji 标注严重程度:`🔴` / `🟡` / `🟢`
- 结论前置:先写结论,再补 1 句数据佐证
- 这是"关键发现",不是"后续建议"
- 若部分模块缺少明细数据,只能基于已有信息下结论,不得虚构分布或样例判断

提炼优先级:
1. 最终决策:当前淘汰或保留是否合理,属于明显失效还是边界出局
2. 数据质量:是否存在高缺失、高集中、低变化度等画像问题
3. 区分与稳定性:IV、KS、AUC、PSI、RC、mono 中哪一项主导结论
4. 分箱表现:哪个 bin 最值得注意,是贡献信息量还是暴露漂移
5. 相关性:是否存在高相关替代,是否更像特征簇中的一个成员
6. 可保留性:它属于"可用但不稳"还是"基本不值得保留"

写法示例:
- `🔴 稳定性问题主导当前淘汰。PSI 明显超阈值,说明该特征跨期分布漂移较大,不属于轻微边界波动。`
- `🔴 当前特征 IV 过高（{iv:.4f}），疑似数据泄露或标签穿越，建议人工核查特征来源。`
- `🟡 当前特征更像擦线出局。IV 和 KS 仍有一定区分能力,但 RC 或 mono 表现偏弱,导致最终未被保留。`
- `🟢 暂无明显异常。当前画像、区分能力和相关性表现整体平稳,可继续进入后续确认。`

## 降级规则

若字段缺失,按以下方式降级:
- 缺 `decision`:只基于现有 detail 数据写观察,不补造阶段结论
- 缺 `profile_detail`:省略"数据质量与分布画像"中的明细列表,只保留一句"当前无画像明细"
- 缺 `summary_detail`:省略"区分能力与稳定性"中的具体数值,只保留已有结论
- 缺 `bin_detail.bins`:写"当前无分箱明细"
- 缺 `corr_detail.top_related_features`:写"当前无相关性明细"

原则:
- 可以少写,不能编造
- 缺字段时保持结构完整,但不要硬填空内容

## 禁止事项

- 禁止输出"数据来源"单独章节
- 禁止直接把整个 JSON 原样贴进报告
- 禁止把所有 bin 逐行机械复述,造成报告注水
- 禁止把"关键发现"写成行动建议
- 禁止输出未替换占位符
- 禁止在无数据支撑时写"显著有效""明显优于"等强判断
- 禁止把 `1.0` 误写成 `1%`;比例值需明确按比例还是百分比解释
- 禁止在"各阶段指标分布"处省略具体指标名,写成泛化的"指标分布"
- 禁止整篇堆 emoji;emoji 仅用于"核心结论""关键发现"中的重点提示

## 排版与写作约束

### 特征名与变量展示
- 特征名优先采用"英文名(中文释义)"形式
- 变量名首次出现时,优先采用"英文变量名(中文释义)"形式
- 示例:`unique_rate(唯一值占比)`、`max_abs_corr(最大相关系数)`
- 若中文释义已清晰表达,后文可只保留中文

### 数值展示
- 比例值优先转百分比,避免歧义
- 保留位数以可读性优先,不必机械保留全部浮点精度
- 阈值比较场景要保留足够位数,保证判断不失真

### 文风约束
- 用中文写作,术语如 IV、KS、PSI、AUC、RC、bin 可保留原文
- 结论前置,避免大段空泛铺垫
- 不重复解释表格里已经显然可见的信息
- 没有数据支撑的结论不要硬写
- 一句话只表达一个判断,避免欧化长句

### 符号约束
- 数值范围使用 en-dash `-`(如 `0.5-1.0`、`3-4`),禁止使用波浪号 `~`(会渲染为删除线)
