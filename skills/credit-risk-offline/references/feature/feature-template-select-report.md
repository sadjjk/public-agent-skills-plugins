# 特征筛选报告模板

## 执行约束

> ⚠️ **Agent 必读**：生成报告时，将下方「Markdown 模板」中所有 `{{PLACEHOLDER}}` 替换为真实内容后写入文件。
> 每个占位符都必须替换，写入前自检：文件中不得出现任何 `{{` 或 `}}` 字符串。
> 字段语义与数据来源统一以 `feature get_select_report_data` 返回结果为准，不得编造数据。

---

## 报告生成步骤

1. 执行 `feature get_select_report_data --key <feature_key>` 获取完整数据（覆盖全部六章节数据）。
2. 按 Markdown 模板渲染，数据缺失时明确说明，不得留空或编造。
3. 执行 `set_select_report --key <key>` 登记并获取脚本返回的标准报告路径。
4. 将渲染内容写入该路径。
5. 执行 `feature status --key <key>`，确认筛选报告写入后特征组状态已推进到 `F3`。

---

## 占位符填充规则

### `{{FEATURE_DESC_OR_KEY}}`
优先取 `feature_desc`；若为空则回退到 `basic.feature_key`。

### `{{FEATURE_KEY}}`
取 `basic.feature_key`。

### `{{DATETIME}}`
优先取 `basic.generated_at`；若缺失则使用当前时间，格式 `YYYY-MM-DD HH:MM`。

### `{{FEATURE_DEFINITION_TABLE}}`
来自 `basic`，渲染为 Markdown 表格。有值则展示，空值跳过。

字段名用中文（如 `feature_key` → `特征 key`，`sample_key` → `样本 key`，`source_type` → `来源类型`）。

特殊处理：
- `source_type`：`standard_library` → 标准样本库；`file` → 本地文件；`table` → 数据库表
- 本地路径优先写成相对 `project_root` 的路径，避免表格过宽

展示字段清单（按顺序，有值则展示，空值跳过）：

来自 basic：
1. `feature_key` → 特征 key
2. `feature_desc` → 特征描述
3. `sample_key` → 样本 key
4. `eval_label` → 评估标签
5. `source_type` → 来源类型（中文映射）
6. `feature_ref_num` → 全量特征数
7. `selected_num` → 入选数
8. `dropped_num` → 淘汰数
9. `alerted_num` → IV 预警数（>0 时展示）

### `{{STAGE_FUNNEL_TABLE}}`
来自 `stages`，渲染为 Markdown 表格。

表头固定：

| 阶段 | 阶段名称 | 阈值 | 输入 | 保留 | 淘汰 | 保留率 |
|---|---|---|---:|---:|---:|---:|

阈值列要求：不直接裸写技术阈值，补成可读中文口径（如 `IV ≥ 0.01`、`PSI < 0.25`、`满足稳定性阈值`）。保留率转百分比保留 2 位小数。

Stage 6 若有 `basic.alerted_num`，保留列显示为 `保留数（X个需警惕）`。

若无数据，写：`当前无阶段漏斗数据。`

### `{{CORE_CONCLUSION}}`
固定输出 3~4 条短结论，使用顺序 emoji 编号（1️⃣ 2️⃣ 3️⃣ 4️⃣）替代数字序号。

**定位：事实摘要**——只回答"发生了什么"，不做归因分析，不做风险判断。

格式示例：
```
1️⃣ 总保留率仅 1.14%，876 个候选中仅 10 个入选。
2️⃣ 粗筛阶段主导淘汰，单阶段淘汰 852 个特征。
```

必须覆盖：
- 总特征数、最终保留数、整体保留率
- 最大收缩阶段及淘汰量
- 是否存在系统性异常信号（仅定性：有/无）
- 入选结果规模

禁止做归因分析（如"属于整体失效""说明几乎无关联"）——归因留给「关键发现」。

写法：事实 + 数字，点到为止，结论前置。

### `{{STAGE_DIAGNOSIS}}`
按 `stages` 顺序输出，采用"收紧版口径"。

#### 1）无收缩阶段
若连续多个阶段 `drop_count == 0`，允许合并描述，但只能合并相邻阶段。尾部无收缩阶段不可并入"前几关"，必须单独描述。若 `input_count` 已极小（1~2 个），写成"剩余候选极少，未再形成收缩"。

#### 2）有淘汰阶段
固定输出：`### 第 N 阶段：阶段名` → 阶段概览 → 指标分布 → 样例表格 → 阶段结论。

缺少数据时保留标题与概览，缺省子块写"当前无 xxx 数据"，不得臆测。

#### 指标分布
来自 `stages[*].metric_distribution`（按 metric 名索引的字典）。

遍历每个 metric，各输出一行分布。单 metric 阶段输出一行，多 metric 阶段输出多行。

排版：
```
IV 分布：
  - 最小值 0.0003｜P25 0.0004｜中位数 0.0005
  - P75 0.0005｜最大值 0.0094｜均值 0.0006
```

多 metric 示例（Stage 1 数据质量）：
```
Zero Rate 分布：
  - 最小值 0.9042｜P25 0.9300｜中位数 0.9500
  - P75 0.9800｜最大值 1.0000｜均值 0.9500

Missing Rate 分布：
  - ...

Unique Num 分布：
  - ...
```

- 标题必须写具体指标名（`IV 分布：`、`PSI 分布：`、`RC 分布：`），禁止写成泛化的"指标分布："
- 统计标签用中文（最小值、中位数、最大值、均值），P25/P75 保留原写法
- 数值默认保留 4 位小数；极小值（<0.0001）可用科学计数法
- 行内分组用 `｜` 分隔

#### 样例表格

标题固定为：`**淘汰特征代表样例**`
> 图例：⚠️ 临界（接近阈值）｜🔴 最差（明显偏离阈值）

来自 `stages[*].examples`，表头固定：
| 特征 | 指标 | 数值 | 原因 |
|---|---|---:|---|
全量展示该阶段 JSON 返回的 examples，按返回顺序输出，不做截断或挑选。原因来自 JSON `reason` 字段。

"特征"列使用 `英文名<br>中文短释义`（规则见底部「排版与写作约束 · 特征名展示」）

压缩示例：
- `身份证号查询，近 3 个月通过利率档位 1 申请的次数` → `近 3 个月身份证利率档位 1 申请次数`

#### 阶段结论
围绕本阶段数据，包含"判断 + 证据锚点"。按分布与阈值的关系定性：

- **边界收缩**：临界样例接近阈值，中位数/P75 靠近阈值
- **明显失效**：最差与临界样例都明显偏离阈值，分布整体远离阈值
- **系统性倒挂**：`negative_count / count` 很高且 `p75 < 0`，整体分布落入异常区间而非少量极端值拖累

**数据锚定要求（必须执行）**：结论中必须引用具体分布数值，禁止只写定性标签。

- **边界收缩**：引用 P75/中位数与阈值的具体差距（如"P75 = 0.0092，距阈值 0.01 仅差 0.0008"）
- **明显失效**：引用均值/中位数与阈值的倍数关系（如"均值 0.9655，超出阈值 90% 逾 6 个百分点"）
- **系统性倒挂**：引用 negative_count 占比及 P75 方向
- **多指标阶段（如数据质量）**：先判断哪种指标是淘汰主力（引用该指标淘汰数及占比），再对主力指标做分布锚定，次要指标一句带过

### `{{SELECTED_FEATURES_SECTION}}`
来自 `selected_examples.alerted_top` 和 `selected_examples.normal_top`。

若有入选特征：输出两个表格（IV 过高 Top10 + 正常入选 Top10）+ 一句总结。

两个表格表头固定：

| 特征 | 指标 | 数值 | 分类 | 子类 |
|---|---|---:|---|---|

"特征"列使用 `英文名<br>中文短释义`（规则见底部「排版与写作约束 · 特征名展示》）。"分类"用 `category_name`，"子类"用 `sub_category_name`，空值显示 `-`。

总结要求：不能只复述"保留 X 个"，必须补充为什么能留到最后、所属主要类目、是强势入选还是勉强幸存、结果为什么偏窄。仅保留 1 个时写成"单特征幸存解释"。
⚠️ IV 预警数量必须引用 `basic.alerted_num`，不得使用 alerted_top 表格行数（表格仅展示 Top10）。

若无入选特征：`本次无最终入选特征。`

### `{{CATEGORY_AGG_TABLE}}`
来自 `aggregates.by_category`，规则一致。

**忠实输出规则**：直接输出 report_data 原值，不臆造分类名、不跳过条目、不合并"未分类"。"未分类"条目必须展示。

表头固定：

| 名称 | 总数 | 入选 | 淘汰 | 入选率 | 主要淘汰阶段 | 该阶段淘汰数 |
|---|---:|---:|---:|---:|---|---:|

字段映射：`name` → 名称，`total_count` → 总数，`selected_count` → 入选，`dropped_count` → 淘汰，`selected_rate` → 入选率，`main_drop_stage` → 主要淘汰阶段，`main_drop_stage_count` → 该阶段淘汰数。

若无数据，写：`当前无聚合结果。`

### `{{SUB_CATEGORY_AGG_TABLE}}`
来自 `aggregates.by_sub_category`，按 `parent_category_name` 分组展示，全量输出。

**忠实输出规则**：直接输出 report_data 原值，不臆造分类名、不跳过条目。"未分类"条目必须展示。

表头固定：

| 名称 | 所属一级分类 | 总数 | 入选 | 淘汰 | 入选率 | 主要淘汰阶段 | 该阶段淘汰数 |
|---|---|---:|---:|---:|---:|---|---:|

字段映射：同 CATEGORY_AGG_TABLE + `parent_category_name` → 所属一级分类。

若无数据，写：`当前无聚合结果。`

### `{{CATEGORY_AGG_SUMMARY}}`
表格后补 1 句判断。关注：候选是否集中在单一 category、主要淘汰是否集中在同一阶段、是否属于整池共性问题。优先写出最大 category 的候选占比。若高占比 category 的主要淘汰阶段一致，判断为整池共性问题。若无数据：`当前无法基于 category 维度做聚合判断。`

### `{{SUB_CATEGORY_AGG_SUMMARY}}`
表格后补 1 句判断。关注：是否由单一子类主导、入选是否过于集中、是否暴露候选池冗余不足。若 top1 sub_category 占比显著，直接写"由单一路子类主导"。若最终入选极少，判断是否暴露整批同口径失效。若无数据：`当前无法基于 sub_category 维度做聚合判断。`

### `{{KEY_FINDINGS}}`
**定位：诊断判断**——回答"为什么"和"意味着什么"，做归因、判风险、评估可推进性。

必须输出 2-4 条；若确实无明显异常，写 1 条"🟢 暂无明显异常"。

**核心规则：不重复「核心结论」已说的事实数字，只做核心结论未覆盖的判断层输出。**

格式：
- 每条以前缀 emoji 标注严重程度：`🔴` / `🟡` / `🟢`
- 结论前置，再补 1 句证据锚点（引用分布特征或结构性信号，不重复核心结论数字）

严重程度：
- `🔴`：系统性异常（RC 全负、PSI 大面积超阈值）、整池失效、几乎无特征入选
- `🟡`：边界收缩、入选偏窄、类目高度集中、维度多样性不足
- `🟢`：筛选过程符合预期，保留结果具备继续推进条件

提炼优先级（按判断深度排序）：
1. **归因判断**：最大收缩是边界收缩还是整体失效？贴线还是远离阈值？
2. **结构性风险**：是否存在系统性异常？
3. **入选质量**：维度是否单一？仅幸存还是强势入选？
4. **候选池诊断**：category / sub_category 集中度是否暴露整批共性问题？
5. **可推进性**：当前结果是否具备继续推进条件？

写法示例：
- `🔴 粗筛淘汰属于整池失效而非边界收缩。IV 分布 P75 不到阈值的 1/20，不是贴线失败，而是候选池与目标变量整体无关联。`
- `🟡 入选维度单一。8 个业务特征全部属于多头查询子类，缺乏收入、负债、行为等维度，模型泛化能力存疑。`
- `🟢 精筛后质量达标。Stage 4~6 无淘汰，入选特征在稳定性、风险一致性和独立性方面表现良好，可继续推进。`

## 禁止事项

- 禁止把表格数值完整复述一遍，造成报告注水
- 禁止把"模板优化建议"混入"关键发现"
- 禁止在无数据支撑时写"明显更优""显著有效"等强判断
- 禁止把非相邻无收缩阶段合并成"前几关"一类表述
- 禁止整篇堆 emoji；emoji 仅用于"核心结论""关键发现"中的重点提示

## 排版与写作约束

### 特征名展示
- 统一合并到一个单元格，使用 `<br>` 换行
- 采用"英文特征名完整保留 + 中文短释义精简展示"两行结构
- 中文短释义：数字时间窗整理为"近 3 个月""近 15 天"等中文排版
- 长度控制在 18~24 个汉字，优先保留"对象 + 时间窗 + 指标动作"
- 压缩时优先删除：解释性修饰、重复限定词、冗长介词结构
- 仍过宽时，完整释义转移到正文总结，表格内只保留最小辨识信息

### 文风约束
- 中文写作，术语如 IV、PSI、RC、bin 保留原文
- 结论前置，避免空泛铺垫
- 不重复解释表格已显然可见的信息
- 没有数据支撑的结论不要硬写
- 一句话只表达一个判断

### 符号约束
- 数值范围使用 en-dash `–`（如 `0.5–1.0`、`3–4`），禁止使用波浪号 `~`（会渲染为删除线）
