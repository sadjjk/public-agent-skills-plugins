# OpenClaw Lark Stream Plus

飞书/Lark 插件流式增强配置，让群聊也能流式输出，支持跨插件通信。

## 💬 作者说

国内聊天三巨头——飞书、微信、钉钉，飞书对 Agent 的支持最积极。

流式输出（打字机效果）、Markdown 排版（表格、代码块），体验都是最好的。

钉钉也支持流式，但抠抠搜搜，没用几次就让你付费

微信？流式没有，排版也差点意思。

所以想要流式输出，飞书首选。但飞书还差点小意思：

**1. 群聊硬编码成纯文本**

群聊人多，API 频率扛不住，飞书插件直接把群聊降级为 static。合理，但小群或个人自用群完全没必要降级。想开？改源码。所以有了这个 skill。

**2. 流式卡片吃不到其他插件的内容**

飞书流式输出的机制是独立渲染卡片，OpenClaw 其他插件在 `before_message_write` 里往 `msg.content` 写的内容，流式卡片根本看不到。

所以又改了一处源码，通过 `global.__ocCardAppend` 实现跨插件通信——其他插件往这个 Map 里写，流式卡片终态时自动追加。

## ✨ 功能一览

| 功能 | 说明 | 触发词 |
|------|------|--------|
| 安装飞书插件 | 其他功能的前置依赖 | 开启/关闭飞书流式输出（未安装时自动引导） |
| 流式输出 | 单聊 + 群聊流式，群聊默认 static 降级改为 streaming | 开启/关闭飞书流式输出 |
| 流式跨插件通信 | 其他插件可通过 `appendToMessage` 注入内容到飞书卡片终态 | 开启/关闭飞书流式跨插件通信 |

## 🚀 使用

对 AI 说：

- "开启飞书流式输出" → 开启单聊 + 群聊流式
- "关闭飞书流式输出" → 恢复默认
- "开启飞书流式跨插件通信" → 开启跨插件通信
- "关闭飞书流式跨插件通信" → 关闭跨插件通信

## ⚠️ 依赖

- **openclaw-lark 插件**：未安装时自动引导安装

## 💡 Tips

飞书的群聊太好用了——一人也能建群。钉钉或微信至少要 2~3+ 人才能成群。

一人群聊对 Agent 的意义：**会话隔离**。以前要新建子 Agent 来隔离不同事务，维护成本高。现在建几个一人群，加同一个 Agent，就做到了：

- A 群聊生活，B 群聊工作
- 背后同一个 Agent，共享完整记忆
- 群群隔离，互不干扰

默认群聊需要 @Agent 才响应，配置里关闭即可。
